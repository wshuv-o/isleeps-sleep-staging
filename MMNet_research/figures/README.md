# Figures — generation artefacts

Every figure in the manuscript is vector (PDF) and is listed below with how it was produced and what was changed by hand. Palette, fonts and label style are shared across all figures via the common style block at the top of `make_figures.py` and `make_mm_figs.py` (Helvetica/Arial stack, colourblind-safe categorical palette, no chart junk, no titles baked into the image — captions carry the description).

Two distinct pipelines are used, and which one applies depends on whether the figure is a **diagram** or a **data plot**.

---

## A. Schematic diagrams — AI → XML → draw.io → vector

The architecture diagram is the figure the AI-to-XML-to-draw.io pipeline applies to, because it is a drawn schematic rather than a plot of measured values.

| Figure | Source artefact | Exported vector | In paper |
|---|---|---|---|
| Architecture | `mm_architecture.drawio`, `mm_architecture_v2.drawio` | `fig_architecture.pdf` | Fig. 3 |

**Prompt used to generate the draw.io XML.** The diagram was generated by prompting a large language model for draw.io-compatible `mxGraphModel` XML with the following brief:

> "Produce draw.io XML (mxGraphModel) for a two-stream neural architecture diagram. Left stream: 188 EEG/EOG/EMG features → dense encoder. Right stream: 14 cardiorespiratory features → dense encoder. The two streams meet at a fusion block, which feeds a BiLSTM temporal decoder over the night, which drives two output heads: a 5-class staging head and a binary respiratory head. Include a direct skip connection from the cardiorespiratory encoder to the respiratory head, drawn distinctly. Label every tensor dimension on its edge. Use rounded rectangles, a restrained palette, and orthogonal edge routing."

**Changed by hand in draw.io.** The generated XML gave a correct topology but a poor layout. Manual refinement: re-laid out both streams onto a shared vertical baseline so the fusion block sits centred; re-routed the direct cardiorespiratory skip connection so it no longer crossed the BiLSTM block; corrected two tensor-dimension labels the model had guessed wrong (the fusion output width and the BiLSTM hidden size) to match `mm_feature_net.py`; unified stroke weights; recoloured to the manuscript palette. Version `v2` is the one exported and used.

**Export.** draw.io → File → Export as → PDF, with *crop to content* enabled, *transparent background* on, and *zoom 100%*, giving a true vector PDF with embedded text.

`build_arch_drawio.py` and `make_drawio.py` are the helper scripts used to emit and patch the XML programmatically.

## B. Data figures — plotted directly from the saved result artefacts

These figures plot measured values. They are **not** drawn by hand or by an AI, because every mark in them is a number produced by an experiment — redrawing them in a diagram editor would break the link between the figure and the result, which is the property the reproducibility requirement exists to protect.

All are emitted as **vector PDF** via matplotlib's PDF backend (`savefig(..., format="pdf")`, text kept as text, no rasterisation), so they satisfy the publication-quality vector requirement. Each is regenerated from a saved artifact in `../results/`, so any figure can be rebuilt without retraining.

Manual work was confined to presentation — axis limits fixed to common ranges so panels compare directly, legend placement, and removal of baked-in titles so the LaTeX captions carry the description. `clean_extra_figs.py` strips titles and annotations from earlier drafts of these figures to enforce the graph-only style.

## Reproducing every figure

```bash
python make_result_figs.py     # benchmark, confusion, AHI, severity, baselines, training curve
python make_mm_figs.py         # ablation grid, per-class F1, t-SNE
python regen_hypno_fig.py      # whole-night hypnogram panel (SN90)
python fig_event_locked.py     # per-event-type AUC
```

Each script reads only from `../results/` and writes PDF (and a PNG preview) into this directory. No script retrains a model.

---

## Note on scope

The manuscript's schematic diagram follows the AI → XML → draw.io → vector pipeline in full, with the source `.drawio` files, the prompt, and the hand-refinement all recorded above. The data figures are vector but are plotted from saved experimental artefacts rather than drawn, because their contents are measurements rather than illustrations. If the drawn-diagram pipeline is required for every figure without exception, the data figures would need to be re-drawn by hand in draw.io from the same CSVs — which we would not recommend, as it severs the guarantee that each figure matches the run that produced it.
