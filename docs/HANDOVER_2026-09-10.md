## 4. ISRUC provenance is undocumented — reproducibility risk

Nothing in the repo records where `data/isruc/` came from, and the honest story
matters for a published paper:

- The official host, `dataset.isr.uc.pt`, **did not resolve** on 5 Sep 2026 (DNS
  timeout). Every download link on `sleeptight.isr.uc.pt` points there, so the
  official route was unavailable.
- The corpus was pulled from a **shared MEGA folder** instead, using a minimal
  MEGA client written for the purpose (client-side encryption: the folder key
  lives in the URL fragment, so files arrive AES-CTR encrypted and are decrypted
  locally).

The paper cites Khalighi's ISRUC reference, which implies an official source that
did not work. Anyone rebuilding `data/isruc/` from
[`build_isruc_external.py`](../MMNet_research/preprocessing/build_isruc_external.py)
has no documented way to obtain the inputs.

**Recommended:** re-check whether `dataset.isr.uc.pt` is back up. If it is,
document the official URL. If not, record the mirror and the date the official
host was unreachable, in `MMNet_research/docs/DATA_NOTES.md`.

## 5. Discarded on purpose — the temporal-vs-HMM run

On 8 Sep a commit holding the executed `14_temporal_vs_hmm.ipynb` and its two
result JSONs was dropped from branch history, at the author's direction. The
notebook on `master` is the **unexecuted shell** — same code, empty outputs.

The result it held, which exists nowhere in the repo:

| config | mean | sd |
|---|---|---|
| no BiLSTM \| hmm | **0.7386** | 0.034 |
| BiLSTM \| hmm | 0.7238 | 0.034 |
| BiLSTM \| raw | 0.7194 | 0.033 |
| no BiLSTM \| raw | 0.6903 | 0.034 |

**The BiLSTM is the redundant component, not the HMM.** HMM smoothing carries the
temporal modelling alone (+4.8pp over raw); adding the BiLSTM on top costs 1.5pp.
The best configuration beats the 0.721 staging headline in the manuscript.

This answers the architecture question the paper still treats as open: the honest
design is **asymmetric** — per-epoch into the staging head with HMM decoding,
recurrent context reserved for the respiratory head.

A local-only git tag `rescue/temporal-vs-hmm` (commit `4031134`) still holds the
executed notebook and JSONs on the 2060 box. **It was never pushed**, so it dies
with this machine. If the result is wanted in the paper, either push that tag or
re-run the notebook — the code is safe on `master` either way.
